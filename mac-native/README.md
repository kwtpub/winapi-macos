# Переносная прослойка учебной графики WinAPI для macOS

Скопируйте папку `mac-native` в корень учебного проекта, рядом с его
исходниками, и выполните одну команду:

```sh
./mac-native/run.sh
```

Скрипт соберёт программу и сразу запустит её. Можно также дважды щёлкнуть
`mac-native/run.command` в Finder: запуск откроется в Terminal.
Исходные файлы проекта с `#include <windows.h>` менять не нужно.

Прослойка заменяет используемое в практиках подмножество WinAPI/GDI
нативным окном Cocoa размером 700 × 700. Сообщения `cout` остаются
в терминале. Для управления активируйте графическое окно и используйте
клавиши, которые ожидает ваша программа. Например, в `ExOOP_03A`
клавиши **1–8** переключают этапы демонстрации точки, круга и лица.
Закрытие окна завершает программу во время опроса клавиш или `Sleep()`.
При обычном выходе из `main` окно закрывается.

Нужны macOS и Apple Clang из Xcode или Command Line Tools. Если компилятор
отсутствует, установите инструменты командой `xcode-select --install`.
Для скриптов не требуется Qt или Wine.

## Установка одним бинарником

Установщик `winapi-macos` содержит внутри себя весь переносной комплект.
Его можно скопировать отдельно: дополнительных файлов рядом не требуется.
Бинарник содержит версии для Apple Silicon и Intel.
Архив `mac-native.zip` позволяет перенести папку модуля вручную.
Запустите его из папки нужной практики: он добавит туда `mac-native`.
Например, если установщик лежит в другой папке:

```sh
/абсолютный/путь/winapi-macos
./mac-native/run.sh
```

Если бинарник уже находится в текущей папке, первая команда —
`./winapi-macos`. Для установки, сборки и запуска одной командой:

```sh
/абсолютный/путь/winapi-macos --run
```

Папку назначения можно указать явно:

```sh
./winapi-macos --dir "/путь/к/практике"
```

Установщик не изменяет `.cpp` и `.pro`. Повторная установка одинаковых
файлов безопасна. При конфликте с изменёнными файлами внутри существующей
`mac-native` он отказывается от замены; `--force` разрешает перезапись
файлов комплекта. Собственные изменения прослойки перед этим сохраните.
Установка без `--run` не запускает сборку. Для последующей сборки
программы всё равно нужны Xcode Command Line Tools.

## Выбор проекта и исходников

По умолчанию проектом считается папка, содержащая `mac-native`.
Собираются все файлы `.cpp`, `.cc`, `.cxx` и `.C` в корне этой папки.
Имя исполняемого файла определяется именем папки проекта:
`mac-native/<имя-папки>_native`.

Если в корне несколько программ с собственным `main()` или нужные
исходники лежат в подпапках, перечислите только файлы одной программы:

```sh
./mac-native/run.sh ExOOP_03.cpp Point_03.cpp
./mac-native/run.sh src/main.cpp src/Point.cpp
```

Относительные пути исходников отсчитываются от выбранной папки проекта.
Чтобы использовать один комплект без копирования в другой проект,
укажите `--project`; путь проекта отсчитывается от текущей рабочей папки:

```sh
./mac-native/run.sh --project "../Практика 4"
./mac-native/run.sh --project "../Практика 4" main.cpp Point.cpp
```

Результат и промежуточные файлы остаются в папке самого комплекта
`mac-native`. Ключ `--help` показывает доступные аргументы.

Для сборки без запуска:

```sh
./mac-native/build.sh
```

`build.sh` принимает те же аргументы выбора проекта и исходников;
ключ `--run` добавляет запуск после сборки. Готовую программу также
можно запускать напрямую, без повторной сборки.

При ручном переносе нужны `windows.h`, `gdi_compat.mm`, `build.sh`,
`run.sh` и `run.command`. `mac-native.pri` нужен для qmake, `tests`
содержит проверки прослойки. Файлы `.build/` и `*_native` создаются
при сборке; переносить их не нужно. Проекты со своими зависимостями,
нестандартными параметрами компиляции или иными вызовами WinAPI
могут потребовать дополнительной настройки.

## Qt Creator и qmake

Для проекта qmake добавьте одну строку в `.pro` после настроек `CONFIG`:

```qmake
include($$PWD/mac-native/mac-native.pri)
```

В `ExOOP_03A.pro` она уже добавлена. Откройте `.pro` в Qt Creator,
выберите комплект macOS и соберите обычным способом. В этом варианте
qmake использует перечень исходников из `.pro`.

На macOS файл `.pri` подключает заголовок прослойки, `gdi_compat.mm`,
Cocoa и C++17. Реализация управляет объектами Objective-C вручную,
поэтому `.pri` отключает ARC для компиляции C++/Objective-C++ этого
проекта. На Windows подключаются системный `windows.h` и библиотеки
`user32`, `shell32`, `gdi32`; заголовок прослойки в пути поиска не добавляется.
Безусловные строки с этими Windows-библиотеками из старого `.pro`
следует удалить, поскольку подключаемый `.pri` уже задаёт их через `win32`.

## Поддерживаемые функции и поведение

- `GetConsoleWindow`, `GetWindowDC`, `ReleaseDC` — одно графическое окно
  и общий контекст рисования; поверхность сохраняется до выхода.
- `RGB`, `SetPixel` — цвета RGB и точки; недопустимые координаты или
  контекст дают `CLR_INVALID`.
- `CreatePen(PS_SOLID, ...)`, `SelectObject`, `DeleteObject`, `Ellipse` —
  сплошные перья и контуры эллипсов. Перо шириной 0 рисует линию толщиной 1.
  Предыдущее перо можно восстановить через результат `SelectObject`.
- `GetAsyncKeyState` — цифры, физические латинские буквы A–Z, стрелки,
  пробел, Escape, Enter, Tab, Backspace/Delete, Home/End/PageUp/PageDown,
  F1–F12, цифровой блок и модификаторы Shift/Control/Option/Command.
  Старший бит означает удержание, младший — новое нажатие с прошлого опроса.
  Клавиши учитываются, пока графическое окно получает ввод; при потере
  фокуса состояния сбрасываются.
- `Sleep` — задержка с обработкой событий окна.

Координаты начинаются сверху слева, Y растёт вниз. Рисунок хранится
в bitmap фиксированного размера и сохраняется после перерисовки окна.
Цикл опроса обрабатывает события Cocoa и кратко ждёт их поступления.

Фон по умолчанию синий `RGB(0,0,255)`: именно этим цветом текущие
`Hide()` стирают фигуры. Если в другой практике используется другой
цвет стирания, задайте совпадающий фон при запуске, например:

```sh
env GDI_BACKGROUND=255,255,255 ./mac-native/run.sh
```

Название окна определяется именем собранной программы. При необходимости
его можно задать переменной `GDI_TITLE`, например
`env GDI_TITLE="Практика 4" ./mac-native/run.sh`.

Это подмножество WinAPI для данных практик. Кисти, заливка `Ellipse`,
пунктирные перья, глобальный опрос клавиатуры и создание произвольных
Win32-окон не реализованы. Для совместимости со старым `Circle` удаление
выбранного пера разрешено и возвращает контекст к стандартному чёрному
перу; поведение Windows в этом случае отличается. Все вызовы следует
делать из главного потока. События обрабатываются при `GetAsyncKeyState`
и `Sleep`; длительные вычисления без этих вызовов задерживают обновление окна.

## Диагностика

```sh
env GDI_DEBUG=1 ./mac-native/run.sh
env GDI_AUTOPLAY=1 ./mac-native/run.sh
```

Переменные можно задавать и при запуске готового `*_native` напрямую.
`GDI_DEBUG=1` печатает вызовы рисования. `GDI_AUTOPLAY=1` каждые 0,4 с
имитирует нажатие опрашиваемой клавиши: удобно для последовательного
примера 1–8, но это не проверка реального клавиатурного ввода.
Значение `0` выключает эти режимы.

## Проверка прослойки

Из корня проекта (тест требует графическую сессию macOS):

```sh
clang++ -std=c++17 -fno-objc-arc mac-native/tests/smoke.mm -framework Cocoa -o /tmp/exoop-gdi-smoke
/tmp/exoop-gdi-smoke
/tmp/exoop-gdi-smoke --close
```

Тест проверяет типы и цвета, координаты, стирание контуров, дескрипторы
перьев, ввод через синтетические события Cocoa и потерю фокуса. Снимок
поверхности сохраняется в `/tmp/exoop-gdi-smoke.png`. Оба запуска должны
завершаться с кодом 0; `--close` проверяет завершение при закрытии окна.
